# 视图与交互

## Context

岗位卡有三个业务日期来源：面试 scheduledAt、笔试 deadline、书面 Offer replyDeadline。投递与 OC 节点只有流程位置。近期安排已有跟进中与完成状态的筛选规则。

## Goals / Non-Goals

本轮回答“最近什么时候截止”和“哪些岗位的安排挤在一起”。用户已确定只同步岗位卡，独立待办及其录入、完成与存储均不在本轮范围。

## Decisions

1. 从同一批已加载岗位生成视图数据，以岗位 ID 和节点 ID 定位。日历沿用近期安排的有效性规则，覆盖浏览月份并保留逾期未完成事项。时间线展示有业务日期的节点，已面、已完成和已结束申请标明状态。日期始终表示卡片上的安排或期限，已完成笔试的截止日期不能标为实际完成日。
2. 月历支持上月、下月、今天与选日。宽格展示事项名称，拥挤时显示余数，选日清单展示全部事项。窄格给出标记，具体岗位和时刻在清单里读。面试与截止用文字区分。
3. 时间线按岗位分行，按自然日等距排列。打开时能看到今天，向两侧浏览，岗位名随轴滚动时保持可见。同岗同日多个节点在行内分层。无明确日期的节点可回岗位卡查看。宽度达到 1200px 并排显示岗位与月历，768–1199px 保留桌面卡片和桌面偏好，通过单独的日历入口查看。点击事件定位到对应岗位及节点，修改后返回保留所看的月份或时间范围。
4. 宽屏让岗位卡和月历并排，专门的时间线页使用整行。按内容可用宽度切到单栏，沿用已有模块显隐和岗位排序。手机首页继续原岗位布局，从导航进入日历或时间线，返回时保留列表位置。手机时间线只允许轴内横滑。
5. 可单独打开的网页样例共用真实视图组件，固定样例中的“今天”，与私人岗位隔离。演示入口允许切换空看板、稀疏周、多岗位同日、同岗同日、逾期、跨月 Offer、只含日期、待定轮次、申请结束与恢复、十余岗位密集月。

## Risks / Trade-offs

并排布局是待验证的桌面方案。对照 1024、1440 和 1920px，记录各宽度能同时读到的公司、进展、日期和截止名称。若岗位区在中等宽度开始遮挡动作，提前切成单栏。320 和 390px 检查日期可点、页面无横向溢出、返回位置一致。以实际页面及场景完成情况给出布局取舍。

同一工作台内，确认保存后用最新岗位集合重绘当前可见视图；返回月历或日期轴时沿用选中日期与浏览范围。失败、冲突、提交结果待确定沿用原反馈，重读后反映实际落盘状态。私有站其他已打开设备的自动重读另行规划。
