# 扎口Job · 工作台呈现与操作设计

## Context

[设计基底](../../../docs/design/DESIGN.md) 维护视觉和文案规则，[设计变量](../../../docs/design/tokens.css) 提供对应数值。设计包的桌面与手机 HTML 演示了布局和局部操作。正式页面要读写同一份业务记录，首次打开空看板时从「添加岗位」开始。四份虚构岗位只用于比较设计和验收。

## Goals / Non-Goals

求职者在同一张卡上能认出岗位、找出最近的安排、登记实际发生的事。一次操作在桌面、iOS、Android 上具有相同的对象和结果。视觉以浅色交付。深色仅保留设计包给出的候选变量。邮件、AI 驱动、简历和额外托管方案沿用前两份提案的后续范围。

## Decisions

### 共享岗位动作，按屏幕组织阅读

卡片读取岗位 ID、资料、按登记顺序排列的节点、申请结果和星标。最新进展取最后登记的节点。历史查看位置是界面状态。点「改一面的时间」提交指定节点 ID。从卡上点「标记二面已面」提交当前二面的 ID。撤回提交用户看到的末节点 ID 和版本。这样在手机滑回一面以后，用户仍能安全地更新二面。

桌面同一张卡从公司、职位读到横向进展和更新入口。长流程提供可发现的完整历史入口，长名称可查看全文。空流程以链接或公司和职位识别，补录后仍可打开原链接。星标排序沿用业务规则，同组保留已有次序。

### 两端共用横向时间线

节点从早到晚排列，最新节点在右端，打开时即可看到。按卡片宽度自然显示，纵向滚动浏览岗位，横向滚动回看历史。手机更新菜单使用底部面板。

### 按最近一次实际进展提供按钮

| 当前进展 | 卡面直接显示 |
| --- | --- |
| 收藏，尚无节点 | 已投递 |
| 已投递 | 收到笔试、收到面试 |
| 笔试待完成 | 标记笔试已完成 |
| 笔试已完成 | 收到面试 |
| 本轮待面试 | 标记本轮已面（按实际轮次，如「标记二面已面」） |
| 本轮已面 | 收到下轮面试、收到 OC |
| OC | 收到书面 Offer |
| 书面 Offer | 期限为空时提供「添加答复期限」，已有期限点节点编辑 |
| 已挂或已拒 | 更正或清除结果；恢复跟进后按末节点显示按钮 |

「收到」记录一次新进展；「已面」「已完成」只更新当前节点。面试轮次按已知记录给出可更正的初值，用户可先登记，稍后点节点编辑轮次、时间或期限。只有用户选择新动作才会推进。「更多」中的「其他进展」支持跳步和直接选轮次，包括收藏后直接登记二面。手机需要选择或填写时使用底部面板。

仅链接岗位在标题旁突出「补资料」，其他岗位从「更多」编辑资料。在时间线上点哪个节点就编辑哪个，撤回仅对末节点开放。「结束申请」单独选择招聘方结束或本人拒绝，结果和最后进展同时显示。

### 让时间、结果与颜色各有含义

浅灰背景、白色实心卡片和蓝色操作入口采用同一套 token。待面试日期和时间整体加粗，已面和已投递呈中性，OC 和 Offer 用绿色，笔试截止和 Offer 答复期限用琥珀色并标明类型。「已挂」与「已拒」分别用低饱和红和中性结果标签，旁边保留最后进展。星标表示关注。页面文字用于识别岗位、理解状态、操作和反馈。

正式静态资源提供 MiSans VF 和所需字重，包含相应字体使用说明，在「设置 → 关于」注明来源。四份对照数据同时覆盖中文、拉丁字母、时间数字和输入控件。验收时检查浏览器实际渲染的字体和回退布局。字体参考入口可用于对照资源版本。

### 从已提交记录生成开始页

岗位进展和近期安排共用已读取的岗位集合。面试时间、未完成笔试截止和 Offer 答复期限来自对应节点，保留日期或具体时刻的精度。申请结束后移出待跟进安排，清除结果后重新计算。共用布局与设备覆盖通过数据提案中的偏好接口读写，用户可调整模块显隐、顺序并恢复沿用共用布局。

### 按保存结果呈现反馈

组件经应用接口提交业务动作。静态版以 IndexedDB 事务完成为准，Sites 以服务端确认及其返回的记录为准。提交中、明确失败、结果未知、版本冲突分别呈现。遇到未知或冲突允许刷新核对，失败信息留在相关操作处。设置的导出和导入复用整板接口，由其判断目标是否为空以及整包恢复结果。

### 从主屏幕进入同一应用

为各构建入口配套提供应用 manifest、图标及适应该部署路径的启动地址，使用各系统支持的添加方式。Sites 继续通过站点身份进入个人看板。静态版读取当前运行环境可访问的本地存储。验收区分主屏幕启动与已打开页面断网后编辑。首次离线启动、跨浏览器共享本地数据均不作为交付条件。

## Risks / Trade-offs

- 字体 CSS 可读取但中文字形实际回退。结合实际渲染字体和网络资源记录检查，并分别查看正常和回退布局。
- 多轮节点、长链接与软键盘可能挤掉更新按钮。在 320、390、430px、1024px、中间宽度及常用宽屏检查，移动操作区以 44×44px 为目标，并检查键盘焦点。
- 样稿的提示可能被误认作真实保存。用首次零岗位、重读后的数据、过时撤回和丢失回包验证界面接线。已提交的业务记录由对应数据提案负责。

## Open Questions

在两种手机上验证横向时间线和底部面板，深色主题独立留待后续验证。

### 轻卡片与日期浏览

岗位卡使用浅灰页面上的白色实心卡面。圆角从设计变量按组件取值：桌面卡片 12px、手机 16px；按钮与输入分别 8px、10px；菜单 12px；居中对话框 16–20px；手机面板仅顶部 20px；小标签 4px。节点保持圆形。沿用 MiSans、字号、行高和间距。

约 1024px 宽的岗位卡以信息列 260px、操作列 128px 起步，余宽留给时间线。少量节点靠左，长历史只在轨道内横滑。首次露出末节点；用户回看后，普通重绘和保存提示保留阅读位置。动作始终绑定实际轮次。历史日期降低强调，待面日期和时刻一起加粗。

手机顶栏品牌保持一行，顶栏只呈现品牌与操作。表单使用「日期（可选）」「时间（可选）」，同排时输入框对齐。样稿用于外观与布局参考，岗位的状态、结果、撤回和日期精度以领域规范为准。

已保存岗位同时驱动岗位卡、近期安排、月历和跨岗位时间线。导航与布局见 [日程设计](../view-job-schedule/design.md)。
