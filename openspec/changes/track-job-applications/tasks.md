# 岗位追踪实施清单

## 1. 建档与星标

- [x] 1.1 建立平台无关的 TypeScript 业务模块及岗位、节点、结果和期限类型。通过严格类型检查，并用测试从模块公开入口创建一份空流程、无结果的岗位。
- [x] 1.2 实现按链接收藏、按公司和职位建档、后续补全资料。验证纯链接可创建，补填六项资料仍是同一条记录，同一公司的两个岗位可以分别更新。
- [x] 1.3 实现设置与取消星标及列表置顶规则。验证仅有链接的岗位也可置顶、取消后回到普通组，两次操作均保留原进展和结果。

## 2. 手动登记与更正进展

- [x] 2.1 实现追加已投递、笔试 / 测评、指定面试轮次、OC 和书面 Offer。验收空流程直接记二面、投递后跳过笔试、一面后选二面或直达 OC，每次只增加选中的节点。
- [x] 2.2 实现笔试期限和手动完成，以及面试的待面试、已面、改期和轮次更正。验证到期不自动推进、同一轮改期保留节点标识、修改早期一面保留后续二面和原顺序。
- [x] 2.3 实现书面 Offer 的可选答复期限。覆盖直接登记、OC 后登记、期限留空及事后补填；验证仅日期与含时刻均可回读，到期不推断结果。

## 3. 逐步撤回与申请结果

- [x] 3.1 实现按指定节点撤回末步。验证拒绝删除中间节点、逐次撤回两个末节点、撤回唯一节点后岗位和星标保留，以及空流程上的重复请求不会继续删除。
- [x] 3.2 为更新定义版本条件与冲突结果，以内存测试替身验证两种交错顺序：读到新末节点后提交旧请求，以及业务检查通过后、保存前另一端成功追加节点。两种情况下桌面新增的三面均可回读。
- [x] 3.3 实现已挂、已拒、更正与清除结果，并据此区分跟进中和已结束。验证二面后已挂、Offer 后已拒及清除结果恢复跟进，各次操作均保留原流程和岗位资料。

## 4. 整体验收

- [x] 4.1 从公开业务入口走通「只贴链接收藏、加星、补资料、投递、测评完成、面试改期并标已面、OC、书面 Offer、本人拒绝」，核对每步的当前进展、最终的节点顺序、Offer 期限和结果。
- [x] 4.2 在无浏览器存储和云服务绑定的环境下运行本次业务测试及严格类型检查，确认上述场景可供后续数据和前端提案复用。
