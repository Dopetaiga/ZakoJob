# 数据与后端实施清单

## 1. 适配器与公共契约

- [x] 1.1 接入 `track-job-applications` 提供的业务动作、ID、版本与领域模型；定义岗位读写、偏好读写和备份恢复的入口。用类型检查和契约用例验证稳定 ID、期望版本、目标末节点及冲突结果能完整传递。
- [x] 1.2 在启动入口选择本地或 Sites 适配器；验证静态包可在普通静态服务器运行，默认路径不发起业务 API 请求，Sites 构建只使用配置的站点 API。
- [x] 1.3 实现版本化备份编解码与整包校验。以空流程、首条二面、空期限、仅日期和具体时刻测试往返；用未知版本、重复岗位或节点 ID、非法状态、损坏偏好测试整包拒绝。

## 2. IndexedDB 本地存储

- [x] 2.1 建立独立的岗位与偏好对象存储，接入真实业务动作。用浏览器验证首次为空、已打开页面断网可写、刷新可读，以及修改手机偏好后桌面仍沿用共用布局。
- [x] 2.2 在同一读写事务内核对版本、应用动作并等待事务完成。用两个标签页验证过时撤回被拒绝，再模拟事务中止，重开后核对原记录。
- [x] 2.3 实现跨对象存储的快照导出和空板原子导入。验证只有偏好时恢复成功、已有岗位时被拒绝、导入中途报错时岗位和偏好全部回滚。

## 3. 私有 Sites 与 D1

- [x] 3.1 为实例添加 D1 表迁移并接入可信所有者身份核对。用两份隔离绑定验证初始化均为空、甲乙各自读写；验证匿名和其他身份不能访问甲的岗位、布局或备份接口。
- [x] 3.2 实现按岗位的业务动作 API、原子版本更新和分范围的偏好保存。用两个独立客户端验证保存后重新读取可见，旧客户端的撤回操作保留二面及三面。
- [x] 3.3 实现保存确认、明确失败和未确认反馈。模拟发送前断网、服务端明确拒绝、提交后丢失响应，确认无自动补传；刷新读回真实进展，重送相同操作不会重复追加。
- [x] 3.4 实现 D1 的一致快照导出和同批次的空板断言、岗位写入及偏好替换。在隔离 D1 上验证并发新建先提交则导入被拒，批次中途故障则无部分数据；并发导出只能读到一份完整快照。

## 4. 跨适配器验收

- [x] 4.1 两个适配器运行同一组岗位动作和读写契约用例，核对星标、撤回、已挂 / 已拒、日期精度及布局继承，验证各自存储都能在新会话继续使用。
- [x] 4.2 用虚构岗位执行「IndexedDB → 空 Sites 实例 → 另一空 IndexedDB」往返。核对稳定标识、二面、Offer、期限、已拒与手机和桌面布局；清除结果后可继续撤回末步。补一次非空目标导入，确认原岗位和偏好均保留。
