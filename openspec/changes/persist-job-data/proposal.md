# 扎口Job · 保存与迁移个人看板

## Why

有人希望打开静态网页就能记岗位，有人希望手机和电脑共用一份私有 Sites 看板。两种用法都需要可靠保存同一套岗位进展，也需要在换设备或改用 Sites 时完整带走记录。

## What Changes

- 开源静态版默认使用 IndexedDB，页面打开后可在断网时保存。Sites 版一人一站，通过站点 API 使用本实例的 D1。
- 对同一岗位按版本提交。确认写入后报告成功；明确失败时返回错误，回应丢失时提示刷新核对。Sites 不设置离线写入队列。
- 保存共用的开始页偏好和手机、桌面各自的覆盖设置。提供共用的版本化 JSON 备份，可随时导出；只向岗位数为零的目标整包导入。

## Capabilities

### New Capabilities

- `job-board-persistence` 管理个人看板的读写、实例访问范围、保存确认和并发更新。
- `job-board-backup` 管理本地版与 Sites 版通用的备份格式、导出和空看板恢复。

## Impact

实施依赖 `track-job-applications` 提供的业务动作和领域类型。该变更仍处于提案阶段，业务规则以其能力规范为准。此处提供存储适配器、Sites 数据接口、D1 迁移和备份编解码，前端提案消费其结果。验收使用空实例及虚构记录。

各自部署的用户拥有各自的数据和实例。原型只用来参考 D1 访问与版本写入模式；模板初始化从空看板开始。
