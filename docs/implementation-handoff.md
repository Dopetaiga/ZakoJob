# 扎口Job 首版实施交接单

**给实施主管。** 请按已确定的四份 OpenSpec 组织开发、联调和验收。最终要交付一个用户打开自己的私有 Codex Site 就能用的求职看板，手机和电脑可继续跟进同一份申请。开源静态版提供相同的操作，默认将数据保存在当前浏览器的 IndexedDB，用户无需搭建业务后端。

截至 2026-11-27，四份提案通过 OpenSpec 严格校验，50 项中已验收 47 项。岗位 11/11、数据 12/12、前端 15/18、岗位日程 9/9。前端 3.2、3.3、4.4 等待 iOS 和 Android 真机对照、定稿与主屏幕启动实测。

静态版已用构建产物完成建档、刷新读回并确认零业务 API 请求。独立私有测试站已部署并绑定站主，站主从设置导入了两条浏览器 IndexedDB 导出的虚构岗位。线上 Worker 的导入及随后岗位、偏好读取均返回 200。直接从托管 D1 读回的两条岗位及三份布局，与原备份逐字段一致。恢复到新 IndexedDB 后可清除「已拒」、撤回书面 Offer；对非空目标重复导入，原岗位和偏好完整保留。隔离 D1 另走了应用的备份导出接口和并发恢复场景。[运行与复测](../README.md) · [跨存储验收](../tests/cross-store/ACCEPTANCE.md)

上一版全仓 130 项回归、按状态推进岗位的 8 项跨适配器验收、34 项界面浏览器用例、13 项时间线回归和 7 项 IndexedDB 浏览器用例均通过。原私有验收站已更新。静态版、Sites 版构建与 TypeScript 严格检查均通过。

本轮在 320、390、1024、1440、1920px 核对同日四项、截止事项与来源定位。宽屏可并排阅读岗位和月历，1024px 通过独立日历页保留岗位卡宽度。两种存储均通过改期、完成、撤回、结束与恢复的同页同步用例。打开站点的 `/schedule-demo.html` 可操作十种虚构场景。

## 排工与交接

| 阶段 | 对应原任务 | 怎么做，何时交接 |
| --- | --- | --- |
| 1. 岗位规则 | 岗位 1.1–1.3、2.1–2.3、3.1–3.3、4.1–4.2 | 完成建档、星标、手选进展、轮次更正、逐步撤回和独立结果。先把岗位 ID、节点 ID、期望版本、日期精度和冲突结果交给数据负责人。领域整体验收通过严格类型检查，并在无浏览器、无云绑定的环境跑通公开入口。 |
| 2. 提前做界面 | 前端 1.1–1.2、3.1 | 与阶段 1 同时开工。用设计基底的四份虚构岗位实现桌面卡及两种可操作的手机历史方案。交付可检查实际字形、待面试时间和更新入口的页面。样例只进入演示或测试。 |
| 3. 统一数据接口 | 数据 1.1–1.3 | 接收领域类型和动作，向前端交付岗位读写、布局偏好、备份导入导出的调用入口和结果类型。核对静态构建默认选择 IndexedDB、Sites 构建选择站点 API。两个适配器共用版本化备份编解码与整包校验。 |
| 4. 并行实现两种存储 | 数据 2.1–2.3、3.1–3.4 | 接口确定后分两路。一路在浏览器实现事务、双标签页冲突与原子恢复。另一路在隔离的私有 Sites/D1 环境实现所有者校验、条件写入、一致快照与原子恢复。两路分别交付能在新会话读回的数据。 |
| 5. 接上真实岗位和开始页 | 前端 1.3、2.1–2.2、4.1–4.2 | 一条适配器可用即可联调。先走通「手机只贴链接 → 加星 → 补资料 → 登记二面 → 刷新后读回」，再接历史更正、撤回、结果、近期安排和分端布局。Sites 路径可用后，用另一设备重读同一岗位。 |
| 6. 真机选择手机交互 | 前端 3.2–3.3、4.4 | 两个候选能操作时即安排 iOS、Android 真机对照，可与存储联调并行。依据实际操作选定历史方式与更新菜单容器，写回设计基底，再验收正式页面的窄屏、触控、键盘及从主屏幕图标启动。 |
| 7. 两种运行模式总验收 | 数据 4.1–4.2、前端 4.3 | 在两个真实适配器上跑同组契约用例，通过工作台操作保存与备份，再完成「IndexedDB → 空 Sites → 另一空 IndexedDB」往返，检查恢复后还能继续跟进。 |

**第一份可用交付**建议看一条完整的私有 Sites 路径。用户在手机上建一条仅含链接的岗位并加星，在桌面重新读取，补齐公司和职位、直接登记二面。手机刷新后能看到同一岗位和约定时间。主管可以据此尽早确认站点身份、持久化和跨端页面已经接通。

## 主管如何验收

| 现场操作 | 应看到的结果 |
| --- | --- |
| 从二面开始登记，标记已面，之后才选择 OC，再登记带答复日期的书面 Offer。另选一份多轮申请更正一面时间。 | 首条可以直接是二面，完成面试只更新本轮。已知待面日期与时间一起加粗，标记已面后保留时间并降低字重。更正一面保留后续节点。只填答复日期时不补时分。 |
| 在已面的岗位上登记「已挂」，在收到 Offer 的岗位上登记「已拒」，再清除结果。 | 招聘方结束和本人拒绝各自可辨，最后进展可读。结束申请退出待跟进安排，清除结果后恢复仍适用的事项。 |
| 桌面刚加三面，手机仍显示二面并请求撤回。在本地版用两个标签页重复。 | 两种存储都拒绝过时请求，重读后二面和三面均在。若用户重新选择，只能先撤回三面。撤回唯一一步后仍保留岗位和星标。 |
| 在已打开的静态版断网写入并测试事务中止。在 Sites 分别模拟发送前断网、服务端拒绝、提交成功后回包丢失。用另一身份及另一私有实例核对访问范围。 | 本地事务完成才算保存，中止后读回旧值。Sites 区分「未保存」与「未确认是否保存，请刷新查看」，刷新读到实际结果，相同操作重送不重复追加。其他身份无法读写本实例的岗位、偏好和备份。 |
| 将只含日期的期限、精确到时刻的期限和分端布局一起备份并往返恢复。再试非空目标、提交前并发新增、导入中途出错和恢复期间导出。 | 只有偏好的空板可以恢复，含已结束岗位的目标也算非空。失败时岗位和偏好均完整保留。导出对应一个完整快照。往返后 ID、节点顺序、日期精度和布局一致，清除结果后仍可撤回末步。 |
| 在 iOS、Android 上分别用展开和横滑完成「找到青禾 → 回看一面 → 更新二面 → 回到列表」。再从系统主屏幕图标进入看板。 | 两案起始都看得到最新进展。回看一面时更新动作仍指向二面。记录斜滑、列表位置、菜单和软键盘的实测差异后选型。图标进入对应看板，真机结果注明设备及浏览器。 |

## 怎样算交付

每次分派给出提案名和原任务编号。使用 Codex 时，首项可以直接下达：「用 `$openspec-apply-change` 执行 `track-job-applications` 的 1.1，从公开入口创建一份空流程岗位，回报严格类型检查和用例结果。」前端可同时领取 `present-job-board` 的 1.1，接入字体和设计变量。

执行人回报改动位置、可复跑命令或复现步骤、预期结果与实际结果。主管据此复核并勾选对应的原任务。可用 `openspec list --json` 汇总勾选进度，`openspec validate --all --strict` 检查提案格式。

最终一并交付静态版的构建与启动方式、私有 Sites 版的运行与复测入口、四份任务清单的完成情况，以及上述跨端、备份和真机用例的结果。遇到私有实例或真机暂不可用，在对应任务标明待验环境，继续完成独立工作，取得实测结果后再关闭该项。
