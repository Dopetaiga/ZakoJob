# 扎口Job 设计思路

正式规则见[设计基底](DESIGN.md)，所有颜色、字号、圆角和动效变量集中在 [tokens.css](tokens.css)。本页记录影响后续选择的原因。

## 为什么采用紧凑的进度卡

使用者反复做三件事，在桌面扫多份申请、路上快速存一个招聘链接、面试结束后更新当前进展。公司、职位、最近时间和状态动作靠近，能让人直接完成这三个动作。桌面采用纵向列表和卡内横向时间线。本轮采用轻卡片视觉：圆角按组件职责收小，减少辅助按钮和装饰的存在感，但完整横向时间线仍是岗位卡的主要内容，历史阶段继续在时间线上呈现，不用「当前进展摘要 + 折叠历史」替代。同一家公司的两个岗位各有自己的卡片，可以从不同面试轮次开始记。只有链接时先显示域名与路径，用户登记环节后再展示进展。

Miuix 提供圆润、克制的视觉方向。白卡、灰底、间距和 MiSans 的字重足以建立层级。收小圆角后不额外增加明显阴影、渐变或多层描边，把颜色留给待面试、期限、录用与结果，有助于在多张卡里找出「周五 15:00」。已面的文字回到中性色，保留曾经面试的事实。只知道日期时按原精度显示，避免误读截止时刻。完成当前环节的动作按实际轮次生成明确文案（如「标记二面已面」），避免「一面已面」这类按钮被误读为状态描述。

## 为什么把进展、结果和动作分开

「二面 · 已面」和「已挂」可以同时成立。把结果单列能让人看到走到哪一步，也看清由谁结束跟进。卡面按当前状态直接显示常用动作并保留一个主要的下一阶段动作，其余更新统一经一级入口「更多」组织（其中「登记其他进展」承接跳步与选轮次，节点编辑、撤回与编辑岗位资料亦在菜单内），申请结果单独分组。标记已面只改这一轮，收到新消息时再选下一步。回看旧轮次时应明确显示历史编辑对象，正在查看的历史节点不等于当前进程，更新当前进展仍使用当前岗位与节点的标识。

## 手机真机比较什么

手机沿用共用横向时间线，岗位信息在上、时间线居中、操作在下；历史超出宽度时仅时间线区域横向滚动，默认露出最新节点，主动回看后不因重渲染跳回最新。需要验证斜向滚动是否影响浏览其他岗位，以及底部面板对单手操作、软键盘和返回位置的影响。用同一份正在二面的岗位比较「找到岗位、回看一面、标记二面已面」的完整路径，关注阅读位置与操作对象。手机品牌「扎口Job」保持一行，顶栏入口不互相挤压。

## 从样稿到真实看板

先用四份固定样例校准字体、密度与时间层级，再验证真实岗位动作和保存反馈。样稿中的提交提示、自动推面试轮次、固定近期安排均属于演示逻辑。页面需要读取已保存数据，准确区分写入失败、未收到确认和版本冲突。

原始设计包保留了取舍过程和外观对照，样稿仅作外观与布局参考。当前确认浅色。深色 token 留待单独验证，正式页面的字体、窄屏、触控、备份和保存须以实际结果验收。常驻解释型小字（如「点 Offer 节点可补答复期限」）不再出现，需要暴露能力时直接提供对应动作。原始设计包未随本仓库分发，取舍结论以本节文字为准。
