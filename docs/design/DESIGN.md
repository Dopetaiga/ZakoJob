# 扎口Job 前端设计基底

2026-11-27。用于首版设计、实现与验收。服务对象是同时跟进多份申请的求职者，核心任务是快速收藏、扫一眼面试与期限、手动更新进展。开源静态版与私有 Site 版共用交互，适配桌面、iOS 和 Android。

## 视觉基调

保持样稿中一屏可扫多份岗位的紧凑密度，采用接近 Miuix 的浅色 Web 界面。中性灰底上放白色实心卡片，12px 卡间距。本轮方向为「轻卡片 + 完整横向时间线」：圆角按组件职责分配，不再统一使用 24px 卡片、14px 控件；收小圆角后不额外增加明显阴影、渐变或多层描边。蓝色集中在操作与待面试状态。卡片以留白分组，轻阴影仅用于菜单、弹窗等浮层。普通卡片随内容增高，避免为固定行高截掉操作。保留 MiSans、现有字号、行高、卡片间距和舒适留白，信息密度不再收紧。界面文案保持直接，不添加口号、装饰性副标题或常驻的操作教学小字。

圆角按组件职责分配，数值是本轮实现的起点，按实际内容与断点适配，不通过全局替换做成同一种圆角；时间线圆点仍保持圆形。按钮轮廓变小不缩小触控面积，手机触控目标仍至少 44×44px。

| 元素 | 桌面 | 手机 |
| --- | ---: | ---: |
| 岗位卡 | 12px | 16px |
| 常规按钮、输入框 | 8px | 10px |
| 下拉菜单 | 12px | 12px |
| 居中弹窗 | 16–20px，按尺寸选择 | 16–20px，按尺寸选择 |
| 手机底部面板 | — | 顶部两角 20px |
| 小型业务标签 | 4px | 4px |

公司名称两端均以 16px / 600 起步。桌面职位 13px，手机 14px。待面试日期与时间两端整体加粗，桌面 15px、手机 17px，字重 650。时间采用等宽数字特性。控件文字、输入框、公司、英文和数字共用 MiSans，输入框字号以 16px 起步。

接入真实 MiSans VF 可变字体，覆盖中文、英文、数字和 400、500、600、650 字重。预览入口固定为 `misans@5.0.0`。正式交付提供所需 CSS、WOFF2 切片及字体声明，在「设置 → 关于」注明使用 MiSans。以实际渲染的字形、网络资源和回退后的换行共同验证。字体加载失败时使用视觉变量里的系统字体栈。[字体预览入口](assets/misans-webfont.css) · [MiSans 使用说明](https://hyperos.mi.com/font/faq)

| 信息 | 视觉表达 |
| --- | --- |
| 已投递、已面、已完成笔试 | 中性色，保留文字。「已面」只说明参加过 |
| 待面试 | 蓝色节点与文字，已知日期与时间一起加粗 |
| OC、书面 Offer | 绿色辅助标识，两类进展保留各自名称 |
| 笔试截止、Offer 答复期限 | 琥珀色，写明「笔试截止」「答复截至」 |
| 已挂、已拒 | 前者用低饱和红色独立标签，后者用中性标签，同时可见最后进展 |
| 星标 | 金色星形，表示优先关注，和期限各有自己的语义变量 |

颜色与文字或形状配合。浅红底上的「已挂」文字使用 `--zj-red-text`，图形标记可用 `--zj-red`。普通文字对实际背景的对比度至少 4.5:1。深色变量仅作候选，当前确认浅色基底。页面文案用于识别岗位、说明状态、操作与反馈。只填链接的岗位显示域名和可识别的路径，一句「尚未登记进展」已足够。

## 工作台与岗位卡

- **开始页。** 「岗位进展」和「近期安排」按用户偏好显示、排序。默认使用共用布局，手机或桌面可单独覆盖。桌面与手机均将「添加岗位」置于「岗位进展」标题行右侧，与标题和申请数垂直居中。空看板也从这里添加第一份岗位。安装到手机主屏幕后，应可由图标重新进入同一看板。
- **桌面。** 纵向扫岗位，横向看每份岗位已登记的流程。按公司与职位、进展与时间、状态动作的顺序阅读。星标排在普通岗位前，各组沿用已有排序。多轮面试时优先保住当前节点及其时间，横向滚动只发生在时间线区域，避免整个页面横向溢出。岗位卡内部采用左侧岗位信息 / 中间横向时间线 / 右侧操作的阅读顺序；约 1024px 宽的岗位卡可先以岗位信息约 260px、操作区约 128px、时间线占剩余空间为调整起点，按实际内容和断点适配，不在所有窗口宽度下强行固定。对齐的是时间线区域的位置，不要求所有卡片的最新节点落在同一横坐标。
- **岗位识别。** 只填链接或同时填写公司与职位均可建档。只有链接也能打开原链接、加星、补资料、登记进展。岗位标题旁只为辨识信息不足（缺公司或职位）的岗位提供「补资料」入口；资料齐全的岗位经「更多」菜单的「编辑岗位资料」修改，不让每张卡都持续表现为「资料未完成、需要补全」。长公司、职位或链接可换行或截断并提供完整查看入口。地点、薪资、纯文本 JD 按实际资料展示。
- **进展。** 只连接真实登记的节点。卡面按当前进展直接显示常用动作按钮，其中完成当前环节的动作按实际轮次生成明确文案（如「标记二面已面」「标记一面已面」），避免被误读为状态；另保留一个主要的、可预期的下一阶段动作。其余更新统一经稳定的一级入口「更多」组织：其中「登记其他进展」（即其他进展）支持跳步与直选轮次，节点编辑与撤回、编辑岗位资料与查看 JD 亦在菜单内；申请结果相关操作单独分组，入口清楚、容易找到。当前「二面 · 待面试」的 **周五 15:00** 要容易扫到，点「标记二面已面」后保留原时间并降低字重。
- **近期安排。** 从跟进中的岗位读取有效面试、未完成笔试的截止期限、Offer 答复期限。申请结束后从待跟进安排中移出，清除结果后按记录中的有效安排恢复。只有日期就显示日期，到期仍保留用户登记的状态。

## 手机与桌面共用的时间线

完整横向时间线是岗位卡的主要内容，两端都保留。节点从左到右按实际登记顺序排列，保留节点、连接线、阶段名称及已有时间信息；时间线区域保持直接排版，不给每个节点增加胶囊背景或独立小卡片。只显示真实记录，不预画未来轮次、不添加空节点、不展示流程完成百分比；此前「当前进展摘要 + 折叠历史」的方案不作为默认展示，历史阶段继续通过时间线呈现。节点较少时从左自然排列，不强行撑满区域，也不把单个 Offer 节点推到最右侧。

历史节点和已发生的时间降低视觉强调，当前待面试节点突出，下一场待面试的日期与具体时刻一起加粗。OC、书面 Offer、答复期限沿用现有业务语义和颜色；「已挂」「已拒」继续作为独立结果显示，不替换或删除最后一个阶段。

打开岗位卡时直接看到右端的最新进展和时间，卡片宽度决定同时可见的节点数。历史超出可用宽度时仅时间线区域横向滚动，公司、职位和操作区保持固定；用户主动查看较早记录后，不因普通重渲染或保存反馈反复跳回最新。只有发生溢出时才显示相应的方向操作，提供「查看较早进展」和「回到最新」的入口；可以弱化原生滚动条，但不同时移除所有可发现的滚动线索。保持节点文字可读，不通过缩小字体把整条历史硬塞进手机宽度。正在查看的历史节点不等于当前进程：滑到一面时，卡上的完成操作仍明确作用于实际当前轮次，编辑历史节点使用节点自身的编辑入口。

手机采用岗位信息在上、横向时间线居中、操作在下的排布；屏幕变窄时调整排布并保留舒适间距，页面整体不横向溢出，横向滚动仅限时间线内部。

原展开和单节点滑动样例保留在演示页；视觉样稿仅作外观与布局参考。

## 日历与跨岗位时间线

岗位日历与跨岗位时间线已在正式工作台实现，均由同一份日程投影（`listScheduleEvents`）从已读取的岗位卡生成，无需刷新：在日历或时间线中定位并修改后回到原岗位卡直接读取最新状态，切回同页视图时也读取最新岗位数据。日历按月浏览面试与截止、选日查看完整有效安排并定位来源岗位；时间线按岗位分行对齐共同日期轴，支持回看与向前浏览。宽桌面（1200px 及以上）岗位列表与日历并排，时间线独占整行；中等宽度按内容可用宽度切回单栏，手机从导航进入日历或时间线，返回时保留列表位置。方向细节见[日程视图提案](../../openspec/changes/view-job-schedule/proposal.md)。

## 状态推进与保存

| 当前进展 | 卡面直接显示 |
| --- | --- |
| 收藏，尚无节点 | 已投递 |
| 已投递 | 收到笔试、收到面试 |
| 笔试待完成 | 标记笔试已完成 |
| 笔试已完成 | 收到面试 |
| 本轮待面试 | 标记本轮已面（按实际轮次生成文案，如「标记二面已面」），另保留一个主要的下一阶段动作 |
| 本轮已面 | 收到下轮面试、收到 OC |
| OC | 收到书面 Offer |
| 书面 Offer | 通过 Offer 节点的编辑入口添加答复期限（答复期限可选） |
| 已挂或已拒 | 更正或清除结果；恢复跟进后按末节点显示按钮 |

「收到」记录一次新进展；「已面」「已完成」只更新当前节点。面试轮次按已知记录给出可更正的初值，用户可先登记，稍后点节点编辑轮次、时间或期限。只有用户选择新动作才会推进。其余更新经「更多」菜单的「登记其他进展」承接，仅列出进展动作并支持跳步和直选轮次；不添加「点 Offer 节点可补答复期限」之类的常驻解释小字，需要时直接提供「添加答复期限」动作或让 Offer 节点拥有清楚的编辑入口。

在时间线上点哪个节点就编辑哪个（明示当前节点，如「编辑一面」），撤回仅对末节点开放；撤回唯一节点后保留岗位和星标。资料齐全的岗位经「更多」菜单的「编辑岗位资料」修改，不新增进展；「更多」菜单的申请结果分组单独选择招聘方结束（已挂）或本人拒绝（已拒），两者独立于流程并保留最后进展，恢复跟进后恢复按末节点展示按钮。手机需要选择或填写时使用底部面板。

日期与时间表单的标签简化为「日期（可选）」「时间（可选）」，同一行的标签和输入框对齐，不因长括号说明换行而错开；日期精度规则不变，只填日期就只保存、显示日期，不自动补零点或其他时刻。

界面经共享业务入口提交岗位和节点的稳定标识以及期望版本。本地版等 IndexedDB 写入完成再反馈。Sites 版等服务端确认再反馈。提交中、成功、明确失败、回应未知和版本冲突各有反馈。回应丢失提示「未确认是否保存，请刷新查看」，冲突时刷新再选操作。失败与未知信息留在相关操作处，直到解决或用户关闭。

设置提供 JSON 导出与导入。导入仅对提交时岗位数为零的看板开放，已有布局的空看板可以恢复。说明岗位及布局将一起恢复，并展示真实的保存或校验结果。

## 对照与验收

桌面和手机均使用四份虚构数据。青禾科技是星标岗位，经历已投递、一面已面、二面待面试，时间为周五 15:00。栖原软件由二面已面开始并标为已挂。拾光数据从 OC 到书面 Offer，答复截至周四 18:00。第四条只有链接 `https://jobs.example.com/p/42`。样例仅用于设计与验证，新用户打开空看板。

检查 320、390、430px 手机宽度，以及 1024px、常用宽屏和中间窗口。使用长公司名、多节点、无日期、仅日期等内容，核对文字换行、菜单边界、焦点顺序、键盘操作和图标按钮的可访问名称。重点核对：单节点、少量节点、长时间线都能合理展示；手机默认看到最新节点并能方便查看较早记录；日期与时刻完整显示，历史文字不重叠；浏览历史不改变当前进程或操作对象；手机品牌「扎口Job」保持一行不拆行（不再显示「私有站点」标识，顶栏保留刷新和设置），页面整体不横向溢出；原有阶段、结果、撤销、日期精度和保存语义保持正确。线性图标约 16–18px，手机有效触控区目标至少 44×44px。减少动态效果偏好使用视觉变量中的对应规则。视觉验收提供桌面与手机页面截图。

真机触控、实际字形、真实保存与冲突、备份、主屏幕启动分别在前端实施中验证。原参考 HTML 演示了局部布局。实际创建与保存、轮次选择、历史编辑、近期安排与恢复都以业务规范为准。
