# 扎口Job · 前端设计交接简报

> 此文保留出稿前的任务与讨论背景。2026-11-26 已整理出正式的[前端设计基底](design/DESIGN.md)与[前端实施提案](../openspec/changes/present-job-board/proposal.md)。手机两种历史交互均留到真机比较后再选，最新约定见设计基底。

## 这轮请你做什么

请为「扎口Job」定一套适合中文求职看板的视觉基调，用同一组岗位做出桌面和手机样稿。桌面已经选定紧凑工作台的排布。配色、字体、图标、卡片质感，以及手机上怎样看进度，都欢迎你提出有判断的方案。这轮交付用于看样稿、定方向，之后再形成第三份前端 OpenSpec 提案。

## 谁会用它

一个同时跟进多份实习或全职申请的人。早上用电脑时，他想扫一眼星标岗位和近期安排。路上用手机时，他可能只来得及粘贴一个招聘链接。刚面完时，他希望在卡片上直接点「已面」，有了新消息再登记下一步。空看板的首要动作是添加第一份岗位。

产品优先面向 **Codex Sites**，每人使用自己的私有看板，手机和桌面访问同一份数据，使用者无需手动部署后端。开源静态版默认把数据保存在当前浏览器的 IndexedDB。两版共用一套业务交互，覆盖桌面、iOS 和 Android，移动端支持从主屏幕图标启动。首版以手填为主，简历管理已移出范围，邮件驱动与 AI 操作留待后续。

## 一张岗位卡怎样工作

| 用户想做的事 | 界面需要表达的规则 |
| --- | --- |
| 先存下来 | 只填招聘链接即可收藏，也可以只填公司和职位名。公司、职位、链接、地点、薪资和纯文本 JD 都可以后补。只有链接时，应能认出并打开这条记录。 |
| 重点跟进 | 星标后排在普通岗位前。只有链接的岗位也能加星，取消星标后回到普通排序。 |
| 登记下一步 | 用户自己选择已投递、笔试 / 测评、某轮面试、OC（Offer Call，口头录用通知）或书面 Offer。时间线上只出现实际登记的环节。允许直接从二面开始，也允许一面后直接收到 OC 或书面 Offer。 |
| 记清时间 | 笔试可填截止期限并手动标记完成。面试按轮次记「待面试 / 已面」及可选时间。书面 Offer 可单独登记答复期限，只知道日期就只显示日期。期限到了，结果仍由本人填写。 |
| 更正或撤回 | 已有一面、二面时，可以回头改一面的时间。撤回则每次只允许删最后一步。撤回唯一节点后，岗位和星标仍保留。 |
| 登记结果 | 「已挂」表示招聘方结束，「已拒」表示自己主动拒绝。两者都会将岗位归入已结束的申请。一张卡仍可同时显示「二面 · 已面」和「已挂」。结果可更正，清除后恢复跟进。 |

## 已经定下来的交互

**桌面用紧凑的横向进度卡。** 纵向浏览多份岗位，横向阅读单个岗位已登记的过程。公司、职位和星标容易定位。「更新进展」直接放在岗位卡上。下一场待面试的**日期和时间一起加粗**，例如 **周五 15:00**。已经结束的面试时间降低字重。进度点可以用颜色传达状态，同时保留清楚的状态文字。颜色的含义和具体色值由你提案。

**「更新进展」要兼顾两种动作。** 对一份「二面 · 待面试」的申请，可以就地标记「二面已面」，也可以选择新增一轮、登记 OC 或登记书面 Offer。标记已面只更新这一轮。若在同一个菜单里提供「已挂 / 已拒」，请按申请结果分组，保留卡上的最后进展。

**开始页按个人喜好组织。** 「岗位进展」便于扫一遍各家的最新情况，「近期安排」便于查看面试时间、笔试截止和 Offer 答复期限。用户能选择显示哪些模块、调整顺序。手机和桌面默认用共用布局，也可以各自设置。

## 手机先试这一种，再看实尺寸效果

候选方案是卡片上方固定公司、职位和星标，下方默认呈现最新进展，用户可以左右滑看历史。浏览其他岗位仍然是上下滚动。滑回一面时，「更新进展」仍针对这份申请当前的进程。编辑历史节点应能看清自己选的是哪一轮。

请在接近真实手机的宽度下试一次「上下找岗位 → 左右看历史 → 登记下一步」。首次打开能否直接读到最新时间？手指斜着滑时页面是否顺手？读完历史是否找得到更新入口？如果另一种交互更自然，可以拿同一张卡做对照。**手机横滑尚未定案。**

## 可直接拿来出图的内容

以下是虚构的设计样例。请让桌面和手机使用相同的数据，方便判断哪些差异来自布局。

| 岗位 | 已登记的进展 | 样稿要看什么 |
| --- | --- | --- |
| ★ 青禾科技 · 后端开发实习生 | 已投递 → 一面 · 已面 → 二面 · 待面试，**周五 15:00** | 多张卡放在一起时，下一场面试依然好找。点「更新进展」可以直接操作。 |
| 栖原软件 · 平台开发工程师 | 首条记录即「二面 · 已面」，申请结果「已挂」 | 能看清走到了哪一步，也能看清谁结束了流程。 |
| 拾光数据 · 数据工程实习生 | OC → 书面 Offer，答复截至周四 18:00 | 读者一眼能区分答复截止和面试安排。 |
| 仅有链接 `https://jobs.example.com/p/42` | 刚收藏，尚无流程 | 卡片能打开、加星、补资料，无需编造公司名或未来环节。 |

**第一轮请给出一张含多份岗位的桌面工作台和一张实际手机宽度的工作台。** 其中一张展示「更新进展」展开后的样子。简要说明字体层级、颜色怎样标识状态，以及手机采用哪种进度交互。

## 会影响界面文案的保存规则

- 本地版在已打开的页面上可以断网保存。Sites 版收到服务端确认才显示保存成功。明确失败就报错，回应丢失时提示「未确认是否保存，请刷新查看」。
- 如果桌面刚加了三面，手机还停在二面，这时撤回会提示进展已变更，让用户刷新后重新选择。
- 设置里需要给 JSON 备份留入口。两版都支持导出，只有岗位数为零的看板可以导入。导入同时恢复岗位和布局偏好，失败时保留原数据。
