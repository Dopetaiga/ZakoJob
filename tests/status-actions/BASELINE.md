## 用例锁定的行为

依据 design.md「按最近一次实际进展提供按钮」状态表逐行推进：

1. **各状态按钮**：收藏无节点→已投递；已投递→收到笔试、收到面试；笔试待完成→笔试已完成；笔试已完成→收到面试；本轮待面试→「{轮次}已面」（如「二面已面」）；本轮已面→收到下轮面试、收到 OC、收到书面 Offer；OC→收到书面 Offer；书面 Offer→只可点节点补答复期限；已挂/已拒→更正或清除结果。
2. **收到通知时尚未确定时间**：点「收到面试」保存一个待面试节点、时间留空、显示「一面已面」；点该节点补录时间只更正该节点，节点 ID 不变。
3. **跳步与资料补全**：仅链接卡经「其他进展」直接登记二面成为唯一节点；标题旁「补资料／编辑资料」不新增进展；进展选择面板只列进展动作（无公司/职位字段）。
4. **回看旧节点后推进最新**：桌面与窄屏把时间线滑到最早后点「二面已面」，仍只把最新二面标为已面。
5. **结束与恢复**：「结束申请」独立选择已挂/已拒，结果标签与最后进展同时显示；更正已挂↔已拒；清除结果恢复跟进后按钮按末节点恢复；撤回仅删末节点、星标保留。
6. **稳定节点**：编辑、撤回、更正、刷新重读后 `data-step-id` 逐个不变。
7. **保存失败及重读**：IndexedDB 过时撤回 → 「进展已变更」冲突提示、重读可见全部节点、不自动执行；离线本地事务完成即成功并重读；Sites 丢响应 → 「未确认是否保存，请刷新查看」、不自动重试、D1 恰好一次落库、刷新读回；真实 Worker 拒绝过时撤回且不重试。
8. **布局**：桌面 1280 与窄屏 320/390/430 全程可操作，无横向溢出；手机选择/填写用底部面板。
